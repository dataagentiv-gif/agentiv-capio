# Agent · Eksperimen

Branch `agentic_cliping`, prototipe lokal; belum rilis produksi.

## Menjalankan

Pasang `requirements.txt`, jalankan API dan worker CAPIO seperti biasa. Inisialisasi database menambahkan `agent_sessions` dan `jobs.agent_snapshot` secara idempoten. Buka **Agent · Eksperimen** pada halaman input atau `/agent`.

Unggah satu video atau gunakan link YouTube. Sumber disiapkan sekali, lalu Agent membaca halaman transkrip untuk membuat ringkasan dan peta topik dengan kutipan batas yang diperiksa. Ringkasan yang belum mencakup seluruh sumber ditandai parsial. Sampaikan arahan melalui chat setelah sumber siap; tidak ada target jumlah sesi. Cari langsung bila arahan jelas. Putar kandidat beserta konteksnya, lalu **Pertahankan** pilihan. Pilih subset maksimal 20 kandidat per job render. **Render pilihan** memakai halaman template/Custom yang sama dengan pipeline biasa. Hasil muncul di Hasil dan ditautkan dari sesi. Browser boleh ditutup selama operasi.

Sumber, transkrip dan proxy preview disimpan di `DATA_DIR/agent/<UUID>`. Penyapu job tidak menyentuhnya. Hapus sesi melalui UI untuk membebaskan disk; penghapusan diblokir selama operasi/render aktif. Hasil render selesai tetap tersedia. Job gagal yang sumber sesinya sudah dihapus tidak dapat diulang.

Model utama Gemini dipilih dari urutan CAPIO ketika sesi dibuat dan menjadi tier pertama. Jika provider/key gagal, Agent mengikuti tier model cadangan CAPIO setelah mencoba pasangan key/model sesuai urutan router; penggunaan dicatat per model. Batas per putaran: 8 permintaan native total (termasuk rotasi key dan tier), 16 pemanggilan tool, dan deadline CAPIO. Kuota/error/batas menyimpan status gagal yang dapat dicoba ulang; tidak ada loop otomatis. Worker restart memulihkan sesi yang sebelumnya dikerjakan slot tersebut ke status dapat dicoba ulang. Sesi yang masih antre tetap menunggu antrean; jika antrean hilang, batalkan lalu coba ulang.

Riwayat resmi, snapshot tiap shortlist, keputusan editor dan idempotency request disimpan di Postgres. Keputusan memakai versi shortlist; ID kandidat berasal dari sesi dan rentang kata. Transkrip lengkap tersedia lewat tools dan tidak diputar ulang dalam setiap prompt chat. Riwayat tools, termasuk putaran gagal, disimpan sebagai audit per operasi; kelanjutan memakai pesan resmi dan pemahaman editorial JSON. Aturan menyertakan kutipan pesan pengguna; asumsi dan hal belum diketahui dipisahkan. Kandidat ditambahkan, penggantian hanya untuk pending yang secara eksplisit diminta. Kept tetap terkunci dan rejected tidak diajukan ulang. Kandidat invalid diminta diperbaiki sekali. Setelah koreksi, hanya kandidat yang lolos pemeriksaan sumber/durasi/kutipan dipertahankan; kandidat valid tidak hilang karena usulan lain ditolak. Koreksi parsial tidak menghapus pending. Alasan penolakan disimpan pada snapshot. Kandidat baru wajib membaca rentang beserta konteks 15 detik, kemudian kutipan pembuka/penutup dicocokkan dengan batas kata. Kecocokan kata tidak menjamin keutuhan makna. Render membekukan pilihan dan tampilan, tidak menyeleksi ulang, dan mempertahankan batas kata yang disetujui. Pemeriksaan frame adalah empat sampel visual per rentang, bukan pemeriksaan seluruh gerakan.

## Pengujian

`python -m pytest tests/test_agentic.py -q` menjalankan kontrak agent dengan model tiruan. Untuk pengujian Postgres, set `CAPIO_AGENT_TEST_DB` ke database uji; setiap kasus membuat dan menghapus schema unik. Jangan gunakan database produksi. Tes mencakup request duplikat, versi lama, kandidat asing, seek preview, restart, batas pemakaian, rotasi key/model, pembatalan, dan FFmpeg nyata dari upload sampai hasil tanpa transkripsi ulang.

Untuk suite lama, set juga `DATABASE_URL` dan `REDIS_URL` ke layanan uji, serta kredensial dummy. Beberapa tes lama memang memerlukan layanan tersebut. Koneksi Gemini native diuji terpisah dengan key nyata: panggilan tool, penyimpanan JSON, dan melanjutkan di proses Python baru. Tes dengan model tiruan membuktikan alur perangkat lunak, bukan mutu editorial.

Tes browser: siapkan database terpisah bernama `capio_ui_test` dan Redis uji; set `DATABASE_URL`, `REDIS_URL`, serta resolusi paket Playwright (`NODE_PATH` bila memakai runtime bersama). Jalankan `node --test tests/agent_ui.test.cjs`. Tes membuka API di port 18086 dan worker RQ, memakai ASR/model tiruan, menjalankan upload dan FFmpeg nyata, lalu menutup kedua proses. Artefak gambar disimpan di folder sementara yang dicetak tes. Jangan jalankan runtime uji ini sebagai server pengguna.

Verifikasi prototipe sebelum perubahan video-dulu, 1 Oktober 2026: 691 tes Python lulus, 2 dilewati; alur browser upload → feedback → refresh → template → RQ → hasil lulus. Gemini native nyata lolos tool calling, keluaran kandidat terstruktur, pencatatan token ke Postgres, dan pemulihan riwayat di proses baru. Regresi lama memakai fixture yang diperbarui untuk kontrak deadline/pembatalan; ada peringatan cleanup MediaPipe saat proses tes berakhir, tanpa kegagalan tes.

## Evaluasi editorial — menunggu lima sumber + brief pengguna

1. Buat lima sesi dengan sumber/brief campaign nyata berbeda dan minta lima kandidat lewat chat. Simpan putaran awal tanpa feedback. Gunakan model sesi yang sama untuk pembanding; jangan mengganti setelan durasi selama evaluasi.
2. Jalankan `python -m agentic.evaluate UUID1 UUID2 UUID3 UUID4 UUID5 --out data/editorial-eval`. Ini melakukan seleksi satu kali menggunakan transkrip dan model yang sama. Pemakaian tercatat sebagai `agent_eval_baseline`. Jika hasil model tidak valid, evaluasi berhenti; jangan mengisi kandidat palsu untuk mengejar jumlah 5.
3. Berikan hanya `review-packets.json` dan `scores.csv` kepada editor. Pakai preview sumber untuk rentang di paket. Simpan `coordinator-only.json` dan `baselines/` pada koordinator. A/B diacak per kasus; packet tidak memuat label pendekatan. Kandidat yang kurang tetap dicatat sebagai kekurangan, bukan ditambal.
4. Editor mengisi `decision` dengan `accepted`, `revise`, atau `rejected`; skor kecocokan brief dan keutuhan konteks 1–5; kesalahan konteks serius `yes/no`; waktu aktif dan catatan. Catat pasangan yang lebih disukai sebelum membuka label.
5. Setelah penilaian awal, koordinator meneruskan koreksi editor ke sesi Agent, maksimum dua putaran. Ekspor/tinjau kembali kandidat dan catat apakah tiap koreksi dipatuhi. Jangan mengubah kandidat yang dipertahankan. Stopwatch editor menjadi ukuran resmi; penghitung UI adalah perkiraan saat tab terlihat dan pengguna aktif dalam 60 detik terakhir.
6. Catat waktu proses, jumlah request/token, jumlah kandidat, waktu aktif editor, kecocokan, konteks dan kepatuhan koreksi. Bandingkan `editorial_seconds` putaran awal Agent dengan waktu baseline; `operations` menyimpan metrik setiap operasi termasuk kegagalan. `preparation_seconds` memisahkan persiapan sumber dan bernilai 0 ketika memakai cache; `processing_seconds` sesi juga memasukkan persiapan sumber sehingga bukan pembanding langsung. Snapshot shortlist menyimpan metrik tiap putaran. Total sesi mencakup percobaan gagal yang selesai ditangani; tabel pemakaian Gemini adalah sumber audit request, termasuk ketika proses terputus. Jangan menyamakan token dengan biaya aktual akun BYOK.
7. Lanjutkan hanya jika Agent lebih disukai pada minimal 3 dari 5 kasus dan tidak menambah kesalahan konteks serius. Jika tidak, simpan hasil dan perbaiki penyebab sebelum memperluas fitur. Empat video jadi referensi sebelumnya bukan data evaluasi seleksi.
